## 三、完整功能清单

### 3.1 核心工作流（L1-L5 分级）

#### L1: 快速修改（Lite-Lite-Lite）
```
用户输入: "把第二段改得更恐怖一些"
         ↓
    Writer Agent (单Agent直接处理)
         ↓
    输出修改后的段落
```
**耗时**: ~30秒 | **适用**: 局部润色

#### L2: 场景规划（Lite-Plan）
```
用户输入: "创建一个悬疑场景"
         ↓
    Architect Agent → 规划LOCK结构
         ↓
    返回场景大纲（无内容生成）
```
**耗时**: ~1分钟 | **适用**: 结构设计

#### L3: 章节开发（Plan + Execute）
```
用户输入: "写一个3000字的悬疑章节"
         ↓
    Architect → 规划3个子场景 + LOCK评分
         ↓
    Writer → 生成初稿
         ↓
    Critic → 评估质量（LOCK + 8维度）
         ↓
    循环修改直到质量达标（最多3轮）
```
**耗时**: ~5-10分钟 | **适用**: 完整章节创作

#### L4: 故事探索（Brainstorm）
```
用户输入: "帮我设计一个反转情节"
         ↓
    多轮对话式头脑风暴
         ↓
    生成3-5个备选方案
         ↓
    人工选择 → 进入L3执行
```
**耗时**: ~15分钟 | **适用**: 创意策划

#### L5: 全流程编排（Coordinator）
```
用户输入: "完成整部小说的第一卷（10章）"
         ↓
    Commander → 分解为10个L3任务
         ↓
    分析依赖关系（章节顺序）
         ↓
    顺序/并行执行（可暂停/恢复）
         ↓
    生成完整卷册 + 质量报告
```
**耗时**: 数小时（可后台运行）| **适用**: 大规模创作

#### 模块 3: Smart Search（RRF 融合搜索）
```python
# 参考 CCW Smart Search
class SmartSearch:
    def search(self, query: str, mode="fuzzy") -> List[SearchResult]:
        """
        mode 选项:
        - fuzzy: FTS + Ripgrep + RRF融合（默认）
        - semantic: Dense Retrieval + Cross-encoder Reranking
        - hybrid: FTS(50%) + Vector(50%) RRF融合
        """
        if mode == "fuzzy":
            fts_results = self.fts_search(query)
            ripgrep_results = self.ripgrep_search(query)
            return self.rrf_fusion([fts_results, ripgrep_results])
        elif mode == "semantic":
            dense_results = self.dense_search(query)
            return self.rerank(dense_results, query)
```

**特性**:
- FTS5 全文索引（SQLite）
- HNSW 向量索引（Kùzu）
- RRF 排序算法（融合多源结果）

## 六、技术亮点

### 6.1 核心创新点

1. **L1-L5 分级工作流**
   - 从30秒快速修改到数小时大规模创作
   - 自适应复杂度（类似自动驾驶L0-L5）

2. **LOCK + 8维度双评估体系**
   - LOCK: 结构完整性（Lead/Objective/Confrontation/Knockout）
   - 8维度: 写作质量（五感/视觉/对话/角色/节奏/情感/叙事/语言）

3. **RRF 融合搜索**
   - FTS + Vector + Ripgrep 三源融合
   - Reciprocal Rank Fusion 算法排序

4. **Core Memory + Session Clustering**
   - 自动提取核心记忆（CMEM-*）
   - 基于语义的会话聚类（CLST-*）
   - 聚类关系图（depends_on/extends/conflicts_with）

5. **OpenKL 文件契约**
   - 统一的 `.writing/` 目录结构
   - SHA256 引用验证
   - 自动 GC 清理失效引用

### 6.2 技术栈优势

```
前端: HTML5 + Vanilla JS (无框架依赖，轻量)
后端: FastAPI + LangGraph (Python生态)
存储: SQLite (会话) + Kùzu (图谱) + 文件系统
实时: WebSocket (进度推送)
可视化: Plotly.js (图表) + Cytoscape.js (图谱)
```

**优势**:
- ✅ 纯 Python 栈（易维护）
- ✅ 本地优先（隐私）
- ✅ 离线可用（无需网络）
- ✅ 可扩展（模块化架构）
