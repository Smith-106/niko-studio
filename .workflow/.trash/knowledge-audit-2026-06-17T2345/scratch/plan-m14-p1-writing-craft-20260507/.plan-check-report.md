## 问题清单

### Issue #1 — LOW
- **文件**: `TASK-001.json`
- **维度**: 可行性 (插入点)
- **描述**: `insert_after` 引用 "SUBGENRE_RULES Record (line ~296)"，但实际 `SUBGENRE_RULES` 在第 222 行。行号漂移幅度约 74 行。
- **影响**: 低。插入点的语义描述（"在 SUBGENRE_RULES 定义下方"）正确，不会导致插入到错误位置。行号仅作为辅助参考。
- **建议**: 将行号更新为 `line ~222`。

### Issue #2 — LOW
- **文件**: `TASK-002.json`
- **维度**: 收敛标准
- **描述**: `grep -c "CharacterArcType" → >= 10` 计数偏紧。8 个枚举值行 + 1 个 enum 声明行 + 1 个 `ArcAssessment` interface 引用行 = 恰好 10。无容错余量。
- **影响**: 低。若实现时 enum 声明行格式略有不同（如 `export enum CharacterArcType { // 麦基角色弧线` 多行注释），可能导致计数为 9 而判定失败。
- **建议**: 降低为 `>= 9`，或新增一条独立标准 `grep "POSITIVE_CHANGE\|NEGATIVE_CHANGE\|...` 来单独验证 8 个枚举值。

### Issue #3 — INFO
- **文件**: `TASK-004.json`
- **维度**: read_first 完整性
- **描述**: `pattern_reference` 明确引用 `SuspenseAnalyzer.analyzeSatisfactionDensity() at suspense-analyzer.ts line 594-663`，但 `read_first` 仅包含 `craft-catalog.ts`，未包含 `suspense-analyzer.ts`。
- **影响**: 无功能影响。`craft-catalog.ts` 作为 enum+interface+Record 模式的典范是有效的参考文件。但执行者若只读 `read_first` 列表，会错过 `analyzeSatisfactionDensity()` 的关键实现参考。
- **建议**: 将 `suspense-analyzer.ts` 加入 `read_first`，或说明 `craft-catalog.ts` 足以覆盖所需模式。
