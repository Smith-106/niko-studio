# F-007: Narrative Structure Visualization — Product Analysis

## User Value Proposition

为作者提供故事结构的可视化呈现——时间轴、角色关系图谱、情节张力曲线——将 M13-M23 积累的分析数据转化为直观的视觉洞察。这是用户能直接看到、交互的新功能，显著提升产品差异化竞争力。

**核心价值**: 创作洞察可视化 + 结构问题直觉发现 + 产品差异化

## Priority Justification

### Impact vs Effort Matrix

| 维度 | 评估 |
|------|------|
| 用户影响 | Very High（全新交互体验） |
| 市场影响 | High（竞品少见的功能） |
| 技术复杂度 | High（可视化 + 数据管道） |
| 实施工作量 | High（MVP 可控，完整版需多期） |
| 风险 | Medium（可通过 MVP 策略控制） |

**综合优先级**: P3（新功能）— M24 唯一推荐的新功能方向，SHOULD 以 MVP 形态交付。

## Success Metrics

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 功能使用率 | >= 60% 活跃用户尝试 | 使用统计 |
| 用户满意度 | >= 4.0/5.0 | 应用内反馈 |
| 可视化渲染性能 | < 500ms（10 万字小说） | Performance profiling |
| 数据准确性 | 时间轴事件覆盖 >= 90% | 人工抽检 |
| 交互响应 | 所有交互 < 100ms | 用户体验测试 |

## User Stories

### US-001: 作为作者，我希望看到故事的时间轴视图
**动机**: 长篇小说中时间线容易混乱，需要全局视角检查时序一致性
**验收**: 可视化展示章节事件在故事时间轴上的分布，支持缩放和筛选

### US-002: 作为作者，我希望看到情节张力曲线
**动机**: 需要直观了解故事节奏是否合理，哪里需要加强冲突或放松
**验收**: 基于 M23 读者体验模型数据，渲染章节级别的张力变化曲线

### US-003: 作为作者，我希望看到角色出场和互动的关系图
**动机**: 多角色小说中需要确保角色出场均衡、关系发展合理
**验收**: 展示角色共现关系图，支持按章节范围筛选

## Acceptance Criteria

### MVP（M24 交付）

1. MUST 提供故事时间轴视图（章节事件按时间排列）
2. MUST 提供情节张力曲线（基于 M23 hook/cliffhanger 数据）
3. SHOULD 提供基础角色关系图（共现统计）
4. 可视化 MUST 支持 10 万字以上小说的流畅渲染（< 500ms）
5. MUST 集成到现有面板系统（作为新 tab）
6. MUST 支持点击可视化元素跳转到对应章节/段落
7. SHOULD 支持数据实时更新（编辑后自动刷新）

### 非 MVP（M25 延期）

- 角色关系图的动态演化动画
- 多条故事线的并行对比
- 自定义可视化维度
- 导出为图片/PDF

## Dependencies and Sequencing

### 前置依赖
- F-002 SHOULD 先完成（面板架构清晰后再添加新面板）
- F-006 SHOULD 先完成（引擎接口稳定后再接入数据管道）
- M23 读者体验模型数据（已完成，可直接使用）

### 后续影响
- 为 M25 写作会话智能提供可视化基础设施
- 为 F-008 修订工作流提供"修订前后对比"的可视化能力
- 建立可视化组件库，后续功能可复用

### 建议排期
- **Batch 3, Week 7-8**
- 预估工时：7-10 天（MVP）
- MUST 在 F-002 和 F-006 之后开始
- 建议分 3 个子迭代：时间轴 -> 张力曲线 -> 关系图

### MVP 策略

**为什么 MVP 足够**:
1. 时间轴 + 张力曲线已能提供核心价值（结构洞察）
2. 角色关系图基础版（静态共现）即有实用性
3. 完整版可在 M25 迭代，用户反馈指导方向
4. 控制 M24 范围，避免新功能挤压技术债时间

**技术选型建议**:
- 可视化库 SHOULD 选择轻量级方案（如 D3.js 或 Recharts）
- MUST NOT 引入重型框架（如 Three.js）
- SHOULD 复用现有 React 组件体系
