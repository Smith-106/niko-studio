## Themes

### 1. 模块拆分与依赖解耦（8 entries）

M28 最大主题。将 reader-endpoints.ts（1173 行）、Container↔MCP、GatewayDeps、craft-catalog ↔ catalog-loader 四处结构性债务一次性收口。 collectively 教会的是一组**渐进式、零破坏**的解耦手法：

- **叶子组优先拆分**：god module 按依赖拓扑从叶子组开始拆（B personas → C feedback → A analyze → D compare），跨组共享函数最后处理，主文件瘦身放最后以保 re-export 锚。
- **shim + ready guard**：拆分后保留原文件作纯 re-export shim 实现零破坏迁移；模块顶层异步 init（loadCustomPersonas）用 ready guard（导出 getReady() 供路由层 await）消除 race condition。
- **接口 + 动态 require + composition-root**：跨层静态依赖无法一次重构 DI 容器时，先抽接口（IWorkflowEventRelay）、调整 import 方向（gateway-bootstrap 从 container 下沉到 composition-root）、adapters 用 require() 构造实现，是低风险渐进路径。
- **ISP + 兼容别名**：胖接口拆角色接口（GatewayDeps → 6 个 I*Access），保留 `type GatewayDeps = I... & ...` 别名，旧消费者不改即编译，新消费者按需收窄。
- **类型层 + lazy getter**：循环依赖用独立类型层（craft-types.ts，只 import type）+ lazy getter（eager const → getFooCatalog()）打破，reloadCatalog 语义正确。

**Key entries:** learnings-020（reader 8 维度拆分）、learnings-042（叶子组优先）、learnings-054 区段（shim+ready guard）、Container↔MCP 解耦、GatewayDeps ISP、craft-types 循环依赖；P1/P2 analyze 会话；ISS-20260624-001、ISS-20260624-003
**Gaps:** 6 条分散 learnings，无综合 knowhow / architecture-constraints 条目统合「渐进解耦手法集」——这是 M28 复用价值最高的知识，却最脆弱（散在 learnings.md）。
**Health:** 80/100（模式扎实，但缺正式 spec 锚点）

- 领域 MAX_* 常量放共享校验模块，避免端点硬编码

### 4. 测试覆盖率补完（4 entries）

M28 Phase 4 为 30% 无覆盖 MCP endpoints 补契约测试，并建工具：

- **coverage-gap-scanner**：零依赖正则扫描 `src-ts/mcp/routes/*.ts` 的 `export const {name}Routes: GatewayRoute[]`，提取 method/pattern/handler/paramNames，扫描测试文件判定 route module 覆盖（变量名/import 路径）与 handler 覆盖（handler 名），输出 JSON + 表格 + `--check` exit 0/1。教训：结构化但简单的源码，正则足以替代 AST parser，零依赖、CI 友好；跨目录测试用 handler 名覆盖而非文件名覆盖避免误报。
- **route contract tests**：直接 import route module 的 const 数组，断言每元素满足 `{ method, pattern: RegExp, handler: Function }` + 关键路由存在且 pattern 可匹配。不深入 handler 行为，只保路由注册契约稳定。
- **集成审计 near-miss**：审计不必全是 PASS/FAIL；「当前工作但脆弱」标 near-miss + 修复建议，比破坏后处理成本低；HIGH/MEDIUM 缺口必须 0 才通过。

**Key entries:** coverage-gap-scanner、route contract tests、集成审计 near-miss 三条 learnings；P4 analyze 会话；ISS-20260624-002（硬编码 route count 66）
**Gaps:** coverage-gap-scanner 是高复用工具（任何 route-array 项目可复用），但无 knowhow 文档化其用法与扩展点。
