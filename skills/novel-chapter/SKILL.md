# Novel Chapter

## 技能定位

`novel-chapter` 是小说章节创作的主控技能，不负责单点技法教学，而负责把以下环节串成闭环：

1. 识别本轮任务属于新写、续写、重写还是润色。
2. 判断是按大纲推进，还是先做探索性场景规划。
3. 产出章节草稿，并做五维评估与 LOCK 检查。
4. 在分数不足时，调用更细的写作技能做定向修订。
5. 输出可交付正文，以及明确的修改说明或下一章接口。

## 适用场景

- 已有故事项目，需要稳定地推进某一章。
- 已有前文，但本章目标、冲突或节奏还未成型。
- 章节草稿已经存在，需要重写、补强或润色。
- 希望把“写一章”拆成可重复执行的流程，而不是一次性自由发挥。

## 不适用场景

- 只需要生成大纲，不需要正文。
  这时先调用 `outline-generator`。
- 只需要做局部修辞润色，不涉及章节级结构。
  这时优先调用 `revision-craft` 或更细分的技法技能。
- 只需要诊断问题，不要求出正文。
  这时优先调用 `script-doctor`。

## 路由决策

先识别任务，再决定执行分支：

| 条件 | 路由 |
|------|------|
| 有明确 `OUTLINE` 或章节卡，并且要写新章 | `有大纲章节创作` |
| 没有完整大纲，但允许探索剧情方向 | `探索性写作` |
| 已有章节，用户要求改剧情/冲突/对话 | `章节重写` |
| 已有章节，用户只要求润色表达 | `文笔优化` |

如果用户既没有大纲，也不接受探索式分支，而是要求“先给我稳定结构再写”，先调用 `outline-generator` 产出场景卡，再回到本技能。

## 输入检查

执行前必须确认 4 件事：

1. 本章的 POV、主目标、主要阻碍是否明确。
2. 本章与上一章、下一章的连接是否可描述。
3. 是否存在不能破坏的设定约束。
4. 用户更在意哪一项：剧情推进、人物、沉浸感、张力还是文风。

如果以上任一项缺失，就先补成“章节任务卡”，再开始写作。

## 章节任务卡

在真正写正文前，先整理为如下最小输入：

```yaml
chapter_brief:
  chapter_id: ""
  pov: ""
  chapter_goal: ""
  conflict: ""
  stakes: ""
  outcome_target: ""
  continuity_constraints:
    - ""
  style_constraints:
    - ""
```

没有这张任务卡，不进入正文生成。

## 主工作流

### Step 1：装载上下文

- 读取大纲、前一章、角色状态、世界规则和必要笔记。
- 只保留与当前章节直接相关的上下文，避免把无关设定塞进本章。
- 抽取本章必须兑现的 3 类信息：
  - 必须推进的剧情事项。
  - 必须体现的人物变化。
  - 必须种下或回收的伏笔。

### Step 2：确定章节骨架

- 如果已有场景卡：直接确认顺序与功能。
- 如果只有章节目标：拆成 3 到 5 个场景节点。
- 每个场景都要写清：
  - 角色要什么。
  - 阻碍来自哪里。
  - 场景结束后局面如何变化。

必要时使用：
- `outline-generator/templates/scene_card_template.md`
- `outline-generator/techniques/scene-card.md`

### Step 3：生成首稿

首稿必须满足：

- 开场 300 到 600 字内给出情境、人物状态和问题牵引。
- 中段不能只有解释，必须有行动、对抗或决策。
- 章尾必须造成一种变化：局势升级、信息反转、情感落差或悬念。
- 不为了凑字数加入不承担功能的段落。

优先使用模板：
- `templates/chapter_prompt.md`

### Step 4：五维评估 + LOCK 检查

首稿完成后，必须做一次结构化评估。

#### 五维评估

| 维度 | 检查问题 | 低分处理 |
|------|----------|----------|
| `dream` | 读者是否能代入并感受到场景 | 补感官细节、情绪递进、内在冲突 |
| `suspense` | 是否存在持续的问题驱动与压力 | 补威胁、障碍、章尾钩子 |
| `character` | 人物行为是否立体且有动机 | 补行为证据、欲望、代价 |
| `premise` | 本章是否服务整体设定与主命题 | 重写目标链与因果链 |
| `voice` | 叙述口吻是否稳定且可辨认 | 统一语气、句法、措辞密度 |

#### LOCK 检查

- `Lead`：开头是否能拉住读者。
- `Objective`：本章目标是否清楚。
- `Conflict`：阻碍是否具体且升级。
- `Knockout`：章尾是否留下继续读的冲动。

#### 质量闸门

- 任一五维分数 `< 70`：进入定向修订。
- 任一五维分数 `< 60`：不允许交付，必须重写或重修。
- LOCK 任一项明显失效：优先修结构，不先修句子。

### Step 5：定向修订

不要同时大修所有问题。每轮只处理 1 到 2 个最低分维度。

| 低分维度 | 优先调用技能 |
|----------|--------------|
| `dream` | `fictional-dream`、`show-dont-tell` |
| `suspense` | `suspense-craft`、`foreshadowing-craft` |
| `character` | `character-forge`、`true-character` |
| `premise` | `premise-magic`、`worldview-craft` |
| `voice` | `voice-workshop`、`tone-craft` |

当问题属于章节级结构、节奏、重复、口吻漂移时，统一走 `revision-craft`，不要直接散改。

### Step 6：二次评估与决策

修订后重新评估，并输出三种结果之一：

- `APPROVED`：正文可交付，并附下一章接口。
- `REVISE`：正文已有方向，但仍需一轮精修。
- `HUMAN_REVIEW`：存在高风险问题，例如主设定冲突、角色失真、核心剧情跑偏。

## 有大纲章节创作

适用：已有 `OUTLINE` 或场景卡，重点是稳定兑现。

执行要求：

1. 从大纲抽取本章唯一主任务，避免把多个大事件塞进一章。
2. 先确认前后承接，再写本章内部张力。
3. 章尾必须把读者推向下一章，而不是平着收。

## 探索性写作

适用：没有完整大纲，但允许先找方向。

执行要求：

1. 基于既有角色状态，提出 3 个后续走向。
2. 每个走向都要写清：
   - 会把故事推向哪里。
   - 会损失什么。
   - 最适合当前人物的是哪一个。
3. 只选一个方向写首稿，不拼贴多个方案。

如果探索结果反复发散，先暂停正文生成，转去 `outline-generator` 固化结构。

## 章节重写

适用：剧情、冲突、对话或 POV 方向需要重做。

执行要求：

1. 先标出必须保留和允许推翻的部分。
2. 先重写场景功能，再重写句段。
3. 检查重写后的前后章节衔接。

如果修改点超过原章内容的 40%，按“新写一章”处理，而不是局部补丁。

## 文笔优化

适用：剧情不改，只优化阅读体验。

执行要求：

1. 不改事件顺序，不新增关键设定。
2. 重点处理句式单调、描写密度失衡、对白失真、语气漂移。
3. 以 `revision-craft` 为总修订器，必要时再下钻到细分技法。

## 输出契约

最终输出必须包含 2 部分：

```markdown
## Chapter Draft
[章节正文]

## Chapter Report
- task_type:
- chapter_goal:
- achieved:
- unresolved_risks:
- five_dimension_summary:
  - dream:
  - suspense:
  - character:
  - premise:
  - voice:
- next_step:
```
